# 3X-UI — форк с RBAC (admin6501)

Кастомный форк [MHSanaei/3X-UI](https://github.com/MHSanaei/3x-ui) — продвинутой веб-панели с открытым исходным кодом для управления серверами [Xray-core](https://github.com/XTLS/Xray-core) — расширенный встроенной **системой множественных администраторов на основе ролей (RBAC)**, **ограничением для реселлеров (Reseller)** и **полностью офлайн-установщиком** для изолированных или ограниченных серверов.

> [!IMPORTANT]
> Проект предназначен только для личного использования. Не используйте его в незаконных целях или в производственной среде.

## Что добавляет этот форк

- **Управление доступом на основе ролей (RBAC)** — управляйте несколькими администраторами панели на странице **Администраторы**, у каждого одна из четырёх ролей:
  - `super_admin` — полный доступ ко всему (первый/администратор по умолчанию).
  - `manager` — управление входящими и клиентами; **без** настроек панели, шаблона Xray и управления администраторами.
  - `reseller` (реселлер) — ограничен только назначенными входящими; управляет своими клиентами и **просматривает** свои входящие в режиме только для чтения (не может добавлять/редактировать/включать-выключать/удалять входящие).
  - `readonly` — может всё просматривать, но не выполнять операции записи.
- **Журнал аудита (Audit Log)** — каждое действие администратора (создание/изменение/удаление администратора, сброс пароля, …) записывается с указанием исполнителя, цели и времени.
- **Офлайн-пакет установки** — установка на сервер без интернета с помощью самодостаточного tarball (бинарник панели + Xray-core + geo-данные). См. [`offline/`](offline/).
- **Проверка обновлений для форка** — «проверка обновлений» в панели читает релизы из этого форка (`admin6501/3x-ui`).
- **Безопасная миграция в PostgreSQL** — миграция SQLite → PostgreSQL копирует все данные RBAC (администраторы, роли, разрешённые входящие, журналы аудита).

## Распределение трафика по реселлерам

Задайте каждому **реселлеру** общий лимит трафика, и панель будет применять его автоматически:

- Установите **квоту трафика** для реселлера (в ГБ) на странице **Admins** — `0` означает без лимита.
- Потребление считается как **сумма upload + download по всем входящим, назначенным этому реселлеру**.
- Когда реселлер достигает квоты, задача трафика **автоматически отключает все его назначенные входящие**, мгновенно отрезая его клиентов.
- Отключённые так входящие отслеживаются и **автоматически включаются снова**, как только вы повысите или сбросите квоту реселлера.
- **Оверселлинг разрешён** — учитывается только реальное потребление — и каждый реселлер видит своё потребление и квоту на панели реселлера.

## Основные возможности (из 3X-UI)

- **Многопротокольные входящие** — VLESS, VMess, Trojan, Shadowsocks, WireGuard, Hysteria2, HTTP, SOCKS (Mixed), Dokodemo-door / Tunnel и TUN.
- **Современные транспорты и безопасность** — TCP (Raw), mKCP, WebSocket, gRPC, HTTPUpgrade и XHTTP с TLS, XTLS и REALITY.
- **Управление по клиентам** — квоты трафика, даты истечения, лимиты IP, статус онлайн, ссылки для общего доступа, QR-коды и подписки.
- **Поддержка нескольких узлов (Multi-node)**, исходящие и маршрутизация (WARP, пользовательские правила, балансировщики).
- **Встроенный сервер подписок** с [пользовательскими шаблонами страниц](docs/custom-subscription-templates.md).
- **Telegram-бот**, **RESTful API** со встроенным Swagger, **SQLite или PostgreSQL**, **13 языков интерфейса**, тёмная/светлая темы и обеспечение лимитов IP через **Fail2ban**.

## Возможности и параметры панели (этот форк)

Помимо перечисленного выше, панель также включает:

- **Планы / Пакеты** — многоразовые шаблоны клиентов: заполняют трафик, срок и лимит IP одним щелчком.
- **Группы клиентов** — объединяют несколько входящих, чтобы одна подписка выдавала несколько конфигов.
- **Хосты (Hosts)** — публикация произвольных точек подписки (адрес, порт, remark, SNI) для каждого входящего.
- **Шаблон Remark подписки** — формирование имён ссылок из токенов `{{VAR}}` (`EMAIL`, `INBOUND`, `TRAFFIC_LEFT`, `DAYS_LEFT`, `HOST`, …); очистка поля восстанавливает шаблон по умолчанию.
- **Дополнительные форматы подписки** — вывод JSON и Clash (с необязательными правилами маршрутизации) наряду с base64-подпиской.
- **Двухфакторная аутентификация (2FA / TOTP)** для входа администраторов.
- **Вход через LDAP / Active Directory** — аутентификация администраторов панели через каталог.
- **Уведомления по e-mail (SMTP)** — событийные оповещения с STARTTLS/TLS и кнопкой тестового письма.
- **Вебхук внешнего трафика** — отправка событий трафика клиентов на внешний URL.
- **Поддержка прокси MTProto (Telegram)** через встроенный sidecar `mtg`.
- **Переключение календаря Джалали (персидский) / Григорианский** для всех дат.
- **Страница обучения в панели** (только super_admin) — многоязычное краткое руководство по всем разделам панели.
- **Усиленная безопасность** — защита CSRF, заголовки безопасности и настраиваемое время жизни сессии.

## Быстрый старт (онлайн)

```bash
bash <(curl -Ls https://raw.githubusercontent.com/admin6501/3x-ui/main/install.sh)
```

Во время установки генерируются случайные имя пользователя, пароль и веб-путь. Затем запустите `x-ui`, чтобы открыть меню управления (запуск/остановка, сброс учётных данных, управление SSL и т. д.).

## Офлайн-установка (без интернета)

Для серверов без доступа к интернету — или там, где загрузка с GitHub заблокирована:

1. Скопируйте `offline/x-ui-linux-amd64.tar.gz` и `install_offline.sh` на сервер (в любую папку).
2. Выполните:

```bash
chmod +x install_offline.sh
sudo ./install_offline.sh                 # автоматически находит .tar.gz в текущем каталоге
# или укажите явно:
sudo ./install_offline.sh /root/x-ui-linux-amd64.tar.gz
```

Установщик **не делает сетевых запросов** для пакета (бинарник + Xray + geo берутся из tarball), выводит сгенерированные учётные данные **и токен API**, а при обновлении **сохраняет существующий `/etc/x-ui/x-ui.db`**, выполняя миграции (включая таблицы RBAC). Подробнее см. [`offline/README.md`](offline/README.md).

> Готовый офлайн-пакет — **только amd64 / x86_64**. Для других архитектур соберите пакет для нужной архитектуры из исходников.

## База данных

- **SQLite** (по умолчанию) — один файл `/etc/x-ui/x-ui.db`. Без настройки, идеально для малых/средних развёртываний.
- **PostgreSQL** — рекомендуется для большого числа клиентов или многоузловых конфигураций.

Миграция существующей установки SQLite в PostgreSQL (со всеми данными RBAC):

```bash
x-ui migrate-db --dsn "postgres://xui:password@127.0.0.1:5432/xui?sslmode=disable"
# затем задайте XUI_DB_TYPE и XUI_DB_DSN в /etc/default/x-ui и перезапустите:
systemctl restart x-ui
```

Исходный файл SQLite остаётся нетронутым; удалите его после проверки нового бэкенда.

## Переменные окружения

| Переменная | Описание | По умолчанию |
| --- | --- | --- |
| `XUI_DB_TYPE` | Бэкенд БД: `sqlite` или `postgres` | `sqlite` |
| `XUI_DB_DSN` | Строка подключения PostgreSQL (при `XUI_DB_TYPE=postgres`) | — |
| `XUI_DB_FOLDER` | Каталог файла базы данных SQLite | `/etc/x-ui` |
| `XUI_INIT_WEB_BASE_PATH` | Начальный URI-путь веб-панели | `/` |
| `XUI_ENABLE_FAIL2BAN` | Включить лимиты IP на базе Fail2ban | `true` |
| `XUI_LOG_LEVEL` | Уровень логов (`debug`, `info`, `warning`, `error`) | `info` |
